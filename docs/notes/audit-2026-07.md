# Pre-M10 multi-dimension audit — 2026-07-30

Six parallel read-only audits (architecture/patterns, dead code/tooling, performance,
stability/concurrency, security/privacy, and a spec-level MKV/EBML parser deep-dive), followed by
an adversarial verification pass: every High-severity finding was re-derived **blind** (title +
file:line only, no evidence) by an independent verifier, and a sample of Mediums was spot-checked.
Scope exclusions: items already known/deferred to M10 (R8, signing, baseline profiles, CI,
androidTest, HEVC investigation, etc.) were screened out and are not re-litigated here.

## 1. Executive summary

**61 unique findings** (64 raw, 3 cross-audit duplicates merged): **0 Critical · 7 High ·
15 Medium · 39 Low**. All 7 Highs were independently confirmed by the blind verification pass;
one Medium was downgraded to Low (no reachable producer).

| Area | High | Medium | Low |
|---|---|---|---|
| Architecture (ARCH-01..13) | 2 | 3 | 8 |
| Dead code / tooling (ARCH-50..57) | — | — | 8 |
| Performance (PERF) | 2 | 3 | 7 |
| Stability (STAB) | 3 | 6¹ | 1 |

| MKV parsers (MKV) | — | 2¹ | 9 |

**Top 5 by user impact:**

1. **STAB-01** — a transient server blip (restart, proxy 502, VPN handover with Wi-Fi up)
   permanently ERRORs the current download, and the drain loop then walks the rest of the queue
   into ERROR within seconds. No retry exists anywhere; the row's error text ("will retry") is
   false. A queued 40-episode season dies to one blip.
2. **STAB-03** — after process death, the restored player replays the *navigation argument*
   position and auto-plays; the 5-second reporter then overwrites the correct resume point on
   device and server. Watching 40 minutes and returning later can silently reset progress.
3. **ARCH-01** — offline, the library grid silently ignores every applied filter while the UI
   shows an active-filter badge; offline filter facets also ignore `parentId` (cross-library).
4. **STAB-02** — tap Play on a slow server, press Home during the spinner: when the resolve
   completes, an unguarded `context.startService()` throws and hard-crashes the app (API 26+
   background-start restriction).
5. **PERF-01 + PERF-02** — every throttled download-progress write (2–6×/s for the length of a
   transfer) re-parses every downloaded item's full JSON metadata blob *and* stat-walks the entire
   downloads tree; both sit upstream of the `distinctUntilChanged` added in M9, so the M9 fix
   suppresses recomposition but none of the work.

**Campaign-level reassurances** (§5 has the full list): the MKV parsers — the code that rewrites
users' media files — came back with **zero Critical/High**: VINT math, Long-offset arithmetic,
seek-position bases, idempotency and bounds-checking all verified correct against RFC 8794, with
the real ffmpeg fixture hex-dumped to settle the CRC question. No token reaches logs, Room,
WorkManager, or disk (SDK-built URLs never embed it — bytecode-verified); Hilt scoping is clean;
startup does no main-thread I/O; there are no dependency-direction violations; no CVEs at pinned
versions; and the measured grid-scroll performance is untouched by anything found.

## 2. High findings (all blind-VERIFIED)

### STAB-01 · High · data-loss — transient failure permanently ERRORs items; a blip wipes the queue
`data/downloads/.../engine/DownloadQueue.kt:168` · Every non-cancellation exception → row ERROR.
`nextRunnable` selects only QUEUED/DOWNLOADING; `DownloadWorker` maps INCOMPLETE →
`Result.success()` so WorkManager backoff never applies; no attempt counter exists;
`DownloadErrorCopy` writes "The download will retry", which nothing does. The drain loop continues
after each failure, so a server-side failure cascades through every remaining row. Verifier
confirmed the only guarded case is a clean *connectivity* loss (constraint → cancellation →
requeue); a reachable-network/unreachable-server blip is fully exposed.
**Fix (M):** classify transient vs permanent before writing ERROR; transient → keep QUEUED,
increment `attemptCount`, return a retryable outcome the worker maps to `Result.retry()` (existing
EXPONENTIAL/30s backoff); ERROR only past a cap or on permanent failures; break the drain on the
first transient. Existing permanent-failure tests stay untouched.

### STAB-03 · High · data-loss — process-death restore replays stale position and overwrites the real resume point
`player/.../ui/PlayerViewModel.kt:98` · `SavedStateHandle` is only ever read (nav args); nothing
writes live state back. Restored back stack re-opens the player at the position *at tap time* with
`playWhenReady = true`; the reporter's 5-second tick stamps it `toBeSynced` with a fresh
timestamp, so most-recent-wins sync propagates the stale position everywhere.
**Fix (S):** write the live position into `SavedStateHandle` on each reporter tick and prefer it
over the nav argument on construction; optionally restore paused (`wasPlaying` flag).

### ARCH-01 · High · wrong-data — offline grid ignores all filters while the UI advertises them
`data/.../OfflineJellyfinRepository.kt:191-224` · `getItems` never reads `query.filters` (and
`sortBy` degrades to sortName — that half is the logged DECISIONS.md divergence; filters are not);
`ItemDao.pagingDownloaded` has no filter predicates. Meanwhile `getFilterFacets` *does* answer
offline with real facets — and ignores its `parentId`, so a movie library's sheet offers genres
from downloaded TV. Applying a filter offline re-queries and renders the identical unfiltered
grid under a "1 active" badge.
**Fix (M):** either implement the predicate arms in `pagingDownloaded` + pass `parentId` through
facets, or — if offline filtering is out of v1 — return empty `FilterFacets()` offline (the sheet
already renders "nothing to filter by") and log the divergence like the sort one.

### STAB-02 · High · crash — unguarded startService when a resolve completes after backgrounding
`player/.../session/ExoPlayerHandle.kt:203` · `prepare()` → bare `context.startService()`; the
KDoc's premise ("always called from a foreground activity") is false across the resolve
suspension — `viewModelScope` survives backgrounding, and a Play resolve can take ~30 s (ARCH-02).
Home during the spinner + grace window elapsing → `IllegalStateException`, uncaught on
`Main.immediate` → process death. The `onForegroundServiceStartNotAllowedException` override
covers Media3's *promotion* refusal, not this *start* refusal.
**Fix (S):** wrap in `runCatching` (playback works without the service; it's the
background-continue bonus), and/or start the service on the Ready/isPlaying transition instead of
in `prepare()`.

### ARCH-02 · High · hang — the Play path has no call ceiling
`player/.../resolve/PlaybackSourceResolver.kt:44-54` · Every browse call is wrapped in
`withTimeoutOrNull(10_000)` (DECISIONS.md 2026-07-28 — "the exact symptom the DoD rules out");
the playback resolve is not: `getPlaybackInfo` rides the SDK's default ~30 s socket timeout. The
resolver's own KDoc names the hazard but only guards the already-offline case. Server dies after
the last browse call (no probe trigger fires) → Play → full-screen spinner, no in-screen cancel.
**Fix (S):** mirror the browse ceiling — `withTimeoutOrNull` around `remote.resolve(request)` +
`connectionState.reportFailure()` so the probe demotes the server for the next call.

### PERF-01 · High · battery — every progress write re-parses every downloaded item's JSON blob
`data/downloads/.../DownloadRepositoryImpl.kt:74-82,257-283` · `observeDownloads()` maps
`observeAll()` (a `@Transaction` over both download tables, re-emitting 2-3× per throttle tick)
through `toDownloadItems`, which `SELECT *`s every item's `dto` column and
`Json.decodeFromString`s the full DOWNLOAD_FIELDS BaseItemDto (tens of KB) — per item, per
emission, 2-6×/s for the whole transfer. `distinctUntilChanged` sits *after* the map. Scope
(verifier): runs while the Downloads screen's ViewModel is alive — which, per PERF-03, is
effectively from first visit until process death.
**Fix (M):** memoise parsed items keyed on `(itemId, cachedAt)` — `ItemDao.getCacheKeys` already
exists for exactly this shape — or split metadata from byte-counts with a `combine`.

### PERF-02 · High · battery — full downloads-tree disk walk per progress write
`data/downloads/.../DownloadRepositoryImpl.kt:87-95` · `observeStorage()` recomputes
`storage.usedBytes()` — `walkBottomUp().sumOf { length() }`, one stat() per file (media +
subtitles + artwork + one per trickplay tile) — inside the combine, keyed on every
`observeProgress` emission, ≥2/s for hours. `distinctUntilChanged` is downstream of the walk.
**Fix (S):** key the walk on the coarse table shape (itemId + status) plus a 10-30 s ticker while
anything is DOWNLOADING; keep StatFs on the same cadence.

## 3. Medium findings

**STAB-05 (= ARCH-03) — the shared ExoPlayer is never released.** `ExoPlayerHandle` has no
`release()`; `stop()` idles the player (codecs/focus/locks are freed — not a battery bug) but the
playback thread, Loaders, allocator buffers, ffmpeg extension renderer and the never-removed
listener live for the process. Fix S: `release()` on the `PlayerHandle` seam, idempotent, called
from `releaseSession()`/service teardown — not from `onCleared` alone (PiP must survive);
`requirePlayer()` already rebuilds lazily.

**STAB-08 (= MKV-03) — in-place header patch with in-memory-only rollback.** The seek-index
repair writes 26+11 bytes into Void padding in place (write → fsync → verify → rollback only on
verify-fail). An IOException mid-write skips the rollback entirely; power loss can tear the page.
Either leaves a previously-playable file NOT_MATROSKA forever with the DB row still DOWNLOADED —
only remedy is delete + re-download. Window is microseconds and at most once per file. Fix S/M:
try/catch around the patch loop attempting rollback on *any* exception; order the Duration patch
first and SeekHead last (each alone is valid; SeekHead is the idempotency marker, so a torn run
becomes re-repairable); optionally a fsynced sidecar pre-image for full crash recovery.

**STAB-04 — cancel/delete during a transfer orphans a re-created directory** (verified).
`delete()` fires `cancelUniqueWork` without awaiting the Operation; the live worker's
`mkdirs()`/`RandomAccessFile` re-creates the just-deleted directory and writes until the next
`ensureActive()`. The between-files guard doesn't cover the multi-minute media file. Cancel-all
amplifies (N stop/delete/restart cycles). Orphans are invisible to the UI but counted by
`usedBytes()`. Fix M: await the stop; orphan sweep on drain start; batch cancel-all.

**STAB-09 — bulk queue actions churn WorkManager; no drain ownership token** (verified).
Resume-all issues N `REPLACE` enqueues; overlapping old/new drains both run `requeueInterrupted`
(no owner column), so drain B can claim the row drain A still holds a `RandomAccessFile` on — two
writers, one file. Narrow race, real corruption potential. Fix M: repository-level
`pauseAll/resumeAll` (one transition), plus a `claimedAt`/workerId lease column.

**STAB-06 — CancellationException swallowed in both workers.** `DownloadWorker.kt:62` catches the
cancellation every Pause produces, logs it at ERROR ("queue stopped unexpectedly") and returns
`Result.retry()` from a cancelled worker; same at `:99` (promote) and `UserDataSyncWorker.kt:61`;
five more latent sites on the never-cancelled scope (BrowseCacheWriter ×3,
DownloadedMetadataRefresher ×2) plus ARCH-08's `UserDataSyncTrigger.kt:68`. The queue's own
structured cancellation is intact. Fix S: the codebase's established two-catch idiom.

**STAB-07 — process-lifetime scopes have no CoroutineExceptionHandler.** SupervisorJob stops
sibling cancellation but doesn't handle exceptions: one throw from a child of `@ApplicationScope`
or the detached player scope crashes the process and silently kills that machinery (most exposed:
the connectivity probe loop — the app's only offline detector). All current children are
defensive; nothing keeps the next one so. Fix S: add a logging CEH to both providers + harden the
probe loop.

**STAB-10 — Downloads screen combine has no `.catch`; `isLoading` starts true.** One upstream
throw (e.g. `SQLiteBlobTooBigException` on a corrupt dto blob) = permanent silent spinner. The
four `observeStates()` collectors freeze badges the same way; `SettingsViewModel`'s `stateIn`
would *crash* instead. The `.catch` idiom already exists in `ServerSetupViewModel`. Fix S.

**SEC-01 — SDK request logging ships in release** (verified Medium; must-fix). Timber is a
verified no-op in release, but jellyfin-sdk logs every request URL at INFO through the
slf4j-android binding, which is on the *release* runtime classpath (the exclusion is
unit-test-only). Search terms, userId, itemIds, server address land in release logcat (token IS
redacted by the SDK's safeUrl). Exposure: adb, OEM preloads, and support bug reports. Fix S:
configure the binding's level to suppress (do **not** remove the binding — its absence kills UDP
discovery, DECISIONS.md 2026-07-28; do **not** plant a Timber release tree — that would create a
sink where none exists). Verifier suggests `debugRuntimeOnly` + a no-op release binding as the
cleanest shape.

**SEC-03 — credential store wipes the session on transient IOException** (verified).
`EncryptedSecureCredentialStore` treats IOException like GeneralSecurityException:
`deleteSharedPreferences` + recreate. Contradicts SessionRepository's documented contract
("a transient storage failure leaves the stored session alone"). Silent to the user; downloads
park on NO_SESSION. Fix M: wipe only on GeneralSecurityException; rethrow/retry IOException;
surface involuntary session loss as a one-shot message on the auth screen.

**PERF-03 — Downloads projection runs on Main.immediate at 2-6 Hz and never stops.** The collect
body (speed tracker, ratchet, `toGroups` with per-comparison `lowercase()` allocations, 12-field
copy) runs on the main thread per emission; the ViewModel never unsubscribes and tab-switching
saves rather than pops it — so it keeps pulling PERF-01+02 with the screen off. Fix M:
`stateIn(WhileSubscribed(5s))` + projection off-main.

**PERF-04 — the 500 ms player tick recomposes the whole controls layer.** Position rides inside
`PlayerUiState`, read at screen scope; `PlayerActions` is rebuilt each composition (nine unstable
method refs), so TopBar/BottomBar/Scrubber/SheetHost all recompose 2×/s. Bounded by the 4 s
controls auto-hide (hence Medium; zero emissions while paused — verified). Fix M: position/
buffered out of UiState (own StateFlow or `() -> Long` into the scrubber);
`remember(viewModel) { PlayerActions(...) }`.

**PERF-05 — un-remembered action bundles defeat row skipping.** `downloadsActions(viewModel)` /
`queueBulkActions(viewModel)` allocate fresh bundles per composition → every visible queue row
recomposes per progress write (keys ≠ skippability). Fix S: `remember(viewModel) { ... }`.

**ARCH-04 — `api(projects.data)` in `:data:downloads` is wrong and free to fix.** The stated
justification is factually wrong (`JellyfinItem` lives in `:core:common`, already api'd); every
`:data` use is impl-internal; blast radius of `implementation()` is **zero source files**. Fix S
(+ make the five classes exposing `ItemEntityMapper` in public ctors `internal`).

**ARCH-05 — two package cycles inside `:data:downloads`** (root↔plan; root→work→engine→root).
`:player` is a clean DAG. No gate catches cycles. Fix M: move `isFolderItem` → `.plan`,
`SiblingSeeder` → `.engine`, split an `.impl` package; add an import-scan test.

**MKV-02 — unguarded `toInt()` on untrusted Void length.** A >2 GiB declared Void in a >2 GiB
file wraps to a negative array size or ~2 GB allocation; `ensureSeekable` catches IOException only
→ the RuntimeException escapes into the playback coroutine (crash, not FAILED). Adversarial-only
input; no corruption (verify re-walk would roll back). Fix S: cap Void lengths + widen the catch.

## 5. Verified non-problems

Checked and found sound — do not re-audit:

- **MKV parser core** (Fable deep-dive): VINT widths 1-8 + unknown-size sentinel math exact;
  all offsets Long end-to-end (>4 GiB files index correctly); SeekPosition base = Segment content
  start, pinned byte-for-byte by the real-header test; CRC-32 moot (real fixture's Info CRC slot
  is ffmpeg's unwritten Void placeholder — hexdump-verified; CRC'd files always ALREADY_INDEXED);
  idempotency test-pinned byte-identical; no zero-advance loops; bounded allocations; decoy Cues
  can't realistically pass the tile-to-EOF check; all 13 element IDs match the registry.
- **Security posture**: no token in Room (8 entities), no WorkManager `inputData` anywhere,
  SDK-built URLs never embed the token (`includeCredentials=false`; only the hand-built trickplay
  URL carries it); auth interceptor host-check sound; `DownloadActionReceiver` unforgeable
  (not exported, exhaustive action `when`, FLAG_IMMUTABLE everywhere); MainActivity reads zero
  intent data; no custom TLS; no Media3 disk cache; SDK websocket path unused; no CVEs at pinned
  versions; login field handling correct; a Timber release tree is NOT wanted (Timber is already
  a release no-op — planting one would create a sink).
- **Stability**: the `runBlocking` at `StorageLocationManager.kt:100` is not main-thread
  reachable (all callers IO/worker) and has no lock inversion; Hilt receiver injection works
  despite the missing `super.onReceive()` (ASM transform verified by disassembly); the delete
  cascade is process-death-ordered; the queue's own structured cancellation is intact; no
  compound `MutableStateFlow` writes anywhere; no access-before-inject among the 7 `lateinit`s;
  `PlaybackReporter` can't double-report or report after logout; HTTP 416 handling correct.
- **Performance**: grid scroll stays at its measured 0.49 % janky — nothing found contradicts it;
  startup does no main-thread I/O (everything lazy, both `.start()`s only launch); PiP state and
  paused-player ticks conflate to zero work; trickplay is one Coil entry per sprite sheet (no
  per-drag decodes); SiblingSeeder/DownloadedMetadataRefresher batch correctly (no N+1); Room
  indices adequate.
- **Architecture**: Hilt scoping clean (no Activity/Context captures, no expensive unscoped or
  duplicate bindings); module dependency directions clean (no feature→feature, core→data);
  `DelegatingJellyfinRepository` routing uniform across all 12 members with the error taxonomy
  test-pinned; the offline `getItem` placeholder contract is deliberate and covered; Settings/
  Downloads screens are already well-decomposed internally; catalog "unused" suspects
  (coil-network-okhttp via ServiceLoader, convention-plugin string accessors, the SLF4J pairing)
  all verified genuinely used.
