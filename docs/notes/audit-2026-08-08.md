# Fresh audit — 2026-08-08 (correctness, security, performance, UI + re-sweep of quality/architecture/duplication)

Seven parallel auditors over the tree at `ec5d62ea` (main): architecture, code quality,
duplication (re-sweeps with prior-finding verification), plus three dimensions the
2026-08-06 audit never covered — **correctness/concurrency**, **security/data-safety**,
**performance/resource-lifecycle** — and a delegated deep-read of the four biggest
Compose files. IDs in this doc are scoped to this audit; where a prefix collides with an
earlier wave (PERF-01..13, SEC-01..09 in `audit-2026-07.md`), the date disambiguates.
Index claims below were verified with real `EXPLAIN QUERY PLAN` runs; the Haze claim by
disassembling the shipped AAR; every prior-audit verdict by reading code, not docs.

## 1. Executive summary

**The 2026-08-06 remediation held.** All 8 H, all 15 CPX, all 11 HYG, all 10 ARCH and
13/15 DUP findings verified landed in code; zero regressions; two trivial unreached
tails (DUP-6: `DownloadEnqueuer.kt:582` ticks constant; DUP-10:
`DelegatingJellyfinRepository.kt:177` status ints). SyncPlay — last audit's biggest
worry — survived adversarial interleaving analysis clean and is now the most hardened
code in the repo.

The new dimensions found what the style-level audit could not:

- **3 high player-UI bugs** (UI-1..3): the sheet pickers are destroyed by the controls
  auto-hide, the auto-hide timer never resets on interaction, and leaving the player
  breaks edge-to-edge app-wide on API 26–34 (masked on the API 36 test tablet).
- **1 high duplication with behavioural drift** (DUP-1): three SDK-exception→`AppError`
  mappers disagree on 403/404 — a 403 from `/PlaybackInfo` never reaches re-auth.
- **5 high performance findings** (PERF-1..5): an unconditional full-screen Haze render
  pass on every non-player frame, cold-start disk I/O + binder IPC on the main thread,
  two broken indices (missing composite, wrong collation — both proven with query
  plans), and a downloads screen that recomposes wholesale 2–8×/s during transfers.
- **2 medium correctness races** (CORR-1/2): cancel→re-download eats the new download;
  the user-data read-modify-write can revert a watched mark locally *and* on the server.
- **1 governance-record corruption** (QUAL-1): `DECISIONS.md` contains the duplication-
  wave entry **45 times** (commit `10968fb6`), ~750 noise lines breaking chronology.
- **Security: 0 high.** Posture is strong (Keystore-backed tokens, one exported
  component, backups off, traversal-sanitised filenames). One medium UX gap: no warning
  when the configured server is cleartext and non-private (SEC-10).

## 2. High findings

### UI-1. The four `PlayerControls`-hosted sheets are destroyed by the 4-second auto-hide
`player/ui/PlayerControls.kt:115` holds `openSheet` in `remember` inside a composable
that `PlayerScreen.kt:269-276` wraps in `AnimatedVisibility(controlsVisible)`.
`ControlsAutoHideEffect` (`PlayerScreen.kt:585-589`) keeps running while a sheet is
open, so `controlsVisible` flips false, the content is disposed, and the
Audio/Subtitles/Speed/Quality picker vanishes mid-selection — realistically within a
second or two of tapping the chip, since the timer starts before the tap. The KDoc on
`PlayerActions.onOpenDisplaySheet`/`PlayerPanel` (`PlayerUiState.kt:367-406`) names this
exact hazard as why DISPLAY/GROUP/QUEUE were hoisted; the reasoning stopped at 3 of 7
pickers. **Fix:** fold `PlayerSheet` into the screen-level `openPanel` (or suppress
auto-hide while a sheet is open).

### UI-2. `ImmersiveLandscapeEffect` "restores" a decor-fits value it never read — breaks app-wide edge-to-edge on API 26–34
`player/ui/PlayerScreen.kt:701`: `val previousDecorFitsSystemWindows = true` is a
literal (everything else in the effect is captured from the window), and `onDispose`
applies it (`:716`). `MainActivity.kt:84` `enableEdgeToEdge` set it false; single-
activity app, so leaving the player flips the whole app to decor-fitting for the rest
of the process. Masked on API 35+ (edge-to-edge enforced) — i.e. invisible on the test
tablet, live on minSdk 26 through API 34. **Fix:** capture the real value, or drop the
restore entirely.

### UI-3. The controls auto-hide timer never restarts on interaction
`player/ui/PlayerScreen.kt:585`: `LaunchedEffect(shouldHide, timeoutMs)` — seek taps,
chip taps and key presses don't touch either key (the key-runner writes `true` over
`true`, not a state change), so the bar hides 4 s after *first appearance* regardless
of use. This is also the mechanism arming UI-1. **Fix:** a `lastInteraction` counter in
the effect key, bumped from transport callbacks, key runner and chip taps.

### DUP-1. SDK-exception→`AppError` mapping exists ×3 and the copies disagree on 403/404
`core/network/ApiCalls.kt:20-42` (internal), `data/ApiErrorMapper.kt:23-57` (public),
`player/resolve/PlaybackInfoResolver.kt:83-101` (19-line verbatim clone of `ApiCalls`,
copied because `apiCall` is `internal`). Drift: 403 → `Server(403)` in two copies but
`Unauthorized` in `:data`; 404 → `Server(404)` vs `NotFound`; unknown errors logged in
one copy only. `DelegatingJellyfinRepository.kt:36-40` documents "401/403 surfaced so
the session layer can re-authenticate" — a 403 from `/PlaybackInfo` is classified as a
server fault and never reaches sign-out; `DownloadFailure` treats both as PERMANENT by
coincidence, not design. **Fix:** one public mapper in `:core:network` (`toAppError` is
the better-specified); all three paths fold through it; pin the 403/404 answer with a
test.

### PERF-1. Every non-player screen pays an unconditional full-screen offscreen render pass per frame
`app/AppScaffold.kt:174,194`: `hazeSource` is applied to the whole NavHost content on
every non-player destination. Disassembled haze 1.7.2: `HazeSourceNode.draw` has no
guard on whether any `hazeEffect` consumer exists — full-resolution layer record +
resolve every draw pass. On the library poster grid (pushed destination, no app chrome)
the pinned header still carries three 18dp-blur `GlassIconButton`s; wide Home/Libraries
add one blur node per visible glass card. GPU-side, invisible to the baseline profile.
**Fix:** set `HazeInputScale.Auto`/`Fixed(0.5f)`; drop `hazeSource` where the glass
could be flat `mSurface`. Measure with a systrace fling first.

### PERF-2. Cold start does SharedPreferences I/O, a binder IPC and OkHttp/SDK construction on the main thread
`app/JellyboostApplication.kt:45-91`: five `@Inject lateinit` fields force the whole
singleton graph inside `super.onCreate()`. Chain reaches `ApiClientProvider`'s
**constructor** (`ApiClientProvider.kt:36-48`): blocking prefs XML read (+ synchronous
`commit()` fsync on first run, `SharedPreferencesDeviceIdStore.kt:30-34`),
`Settings.Secure` binder read, Ktor/OkHttp + serialization setup — all before first
frame. **Fix:** inject `dagger.Lazy`, `.get().start()` from a coroutine; `by lazy` the
`jellyfin` field.

### PERF-3. No composite `(source, type)` index — offline queries scan the whole browse cache
`core/database/entities/ItemEntity.kt:63-95` has only single-column indices. Verified
plans: `unwatchedDownloadedEpisodes`, `searchDownloaded`, `seasonsOfSeries`,
`allBySource` all pick `index_items_type`, visiting every *browsed* episode ever cached
(multi-KB `dto` blob deserialised per row before `source` discards it); worst is
`ItemDao.kt:163-180` (`SELECT i.*`, no LIMIT) feeding offline "Next up". **Fix:**
`Index(["source","type"])` — verified to flip the plan to a two-column SEARCH.

### PERF-4. `index_items_sortName` is BINARY but both consumers sort `COLLATE NOCASE` — the index is never used
`ItemEntity.kt:61`; proven: NOCASE order → `SCAN + TEMP B-TREE`, index ignored. Consumer
`ItemDao.kt:102-104` is the offline grid's whole key set, re-sorted per page (compounded
by `OfflineJellyfinRepository.kt:240-261` reading the full set then `.drop/.take`).
Pure write-amplification today. **Fix:** migration recreating it as
`(sortName COLLATE NOCASE)`, or drop it.

### PERF-5. Downloads screen recomposes wholesale 2–8×/s during transfers (incl. the Downloaded tab)
Cluster (also found independently by the UI deep-read): `DownloadsScreen.kt:122`
collects a monolithic `DownloadsUiState` (unstable `List`/`Map` fields, fresh instance
per progress tick, no stability config file) — nothing taking `state` can skip.
`DownloadsChrome(state=…)` (`:310/:373/:420`) re-sums every finished item's
`bytesOnDisk` (itself a computed `get()` walk) several times a second;
`downloadedRows` gets a fresh `List<DownloadGroup>` so every visible finished row
recomposes for zero visible change; `RowArtwork`/`QueueRowActions`
(`DownloadRows.kt:194-224`) take whole `DownloadItem`s where a URL and two booleans
would do (PERF-14). Keys/contentType are already correct — this is purely parameter
granularity. **Fix:** scalar params for chrome; memoised group identity (see PERF-11);
narrow row params.

## 3. Medium findings

### Correctness (new dimension)
- **CORR-1** — cancel→immediate re-download: `demoteRunnable` flips to `CANCELLED` and
  the UI instantly offers "Download" (`DownloadRepositoryImpl.kt:678`), but the delete
  cascade behind a ≤5 s `stop()` then reaches the item, finds the *freshly re-enqueued*
  `QUEUED` row (`DownloadEnqueuer.kt:262-287`), and deletes it, directory and all
  (`DownloadDeleter.kt:62-72`). Silent no-download. **Fix:** status-conditional cascade
  (`DELETE … WHERE status='CANCELLED'`) or enqueuer parks while a row is `CANCELLED`.
- **CORR-2** — `UserDataRepositoryImpl.storeLocally` (`:179-204`) is read-modify-write
  outside any transaction; the 5 s progress tick races a cross-screen "mark watched",
  reverts it locally, then pushes stale `played=false` to the server — lost both sides.
  **Fix:** `@Transaction` DAO method or per-`(itemId,userId)` mutex; fix together with
  DUP-5 (same file, same push code).
- **CORR-3** — season cancel loops N single deletes (`DetailDownloadsDelegate.kt:214`),
  each a full stop/restart cycle that starts the next doomed server transcode; the batch
  `deleteAll` exists and embodies the STAB-09 lesson. **Fix:** one `deleteAll(targets)`.
  (Related low: PERF-25's per-item N+1 inside the deleter itself.)

### Security (new dimension; 0 high — full clean-list in §6)
- **SEC-10** — cleartext/user-CA allowance is global (`network_security_config.xml:12-22`)
  — necessarily, since users type arbitrary addresses — but nothing warns when the
  resolved server is `http://` and non-private. The one realistic remote token-theft
  path (port-forwarded server reached from public Wi-Fi). **Fix:** one-time warning in
  `ServerSetupScreen` for cleartext + non-private-range hosts.

### Architecture
- **ARCH-1** — `:data` exports the whole SDK as `api` (`data/build.gradle.kts:15-16`) on
  a self-contradictory comment; the SDK-naming publics (`ItemMapper` etc.) have zero
  external consumers (grep-verified). Demoting to `implementation` makes the plan's
  "UI never sees SDK" invariant *compiler*-enforced for the `:data`-fed features,
  closing the FQ-reference gap detekt can't see. Sequence after the ARCH-2 sweep.

### Performance
- **PERF-6** — `downloadShape()` cold flow subscribed ×2 → 2–3 unindexed full-table
  scans per progress sample (`DownloadRepositoryImpl.kt:198-202`); the fix pattern
  (`downloadStates` stateIn, `:105-118`) is one screen up. **Fix:** same `stateIn`.
- **PERF-7** — one progress sample = two auto-commit UPDATEs (`DownloadQueue.kt:831,860`)
  → `observeAll()` re-runs ×2, each emission probing `items` via `getCacheKeys` at
  4–8 Hz. **Fix:** one `@Transaction` wrapping both; gate the probe on shape change.
- **PERF-8** — no `distinctUntilChanged` on any DataStore flow
  (`DataStoreAppPreferences.kt`): any pref write re-emits all seven, and the volume-id
  flow restarts the full downloads-tree `File.walk` PERF-02 (July) moved off the
  progress path. **Fix:** `.distinctUntilChanged()` per flow.
- **PERF-9** — `observeBytesOnDisk` (`DownloadRepositoryImpl.kt:192-195`) is the one
  repo flow without `distinctUntilChanged`/`flowOn`; open detail pages re-run the SUM on
  every file-progress write app-wide. **Fix:** match its five siblings.
- **PERF-10/11** — per-tick rebuilds over *all* downloads: `DownloadProgressRatchet`
  set+map over the whole table (`DownloadsViewModel.kt:91`); `toGroups()` re-groups/
  re-sorts/re-lowercases the finished half (`DownloadsUiState.kt:299-325`). **Fix:**
  pass the queue subset; memoise on a cheap signature.
- **PERF-12** — the 64 KB copy buffer never fills: okio returns ≤8 KB per `read`, and
  each goes straight to an unbuffered `RandomAccessFile.write`
  (`FileDownloader.kt:254,286,295`) — ~15,300 write syscalls/s on gigabit. **Fix:**
  fill the buffer before one write, or `sink().buffer()`.
- **PERF-13** — `MkvClusterScanner` allocates 2 arrays per 8 KB chunk (~976k for 4 GB)
  and scans byte-by-byte on the transfer thread (`MkvClusterScanner.kt:104,121-141`).
  **Fix:** shift carry in place; skip to next `0x1F` lead byte.
- **PERF-15** — download notification sticks on "Preparing…" after every pause/resume/
  retry: singleton `DownloadNotifier.lastPosted` survives worker runs and is never
  reset (`DownloadNotifier.kt:53,93`; `DownloadWorker.kt:86`). **Fix:** reset in
  `onIdle()`.
- **PERF-16** — `hasNetwork` cold `callbackFlow` collected ×2 forever → two binder-
  registered system callbacks (`AndroidConnectivityMonitor.kt:36-77`;
  `ConnectionStateProvider.kt:115,235`). **Fix:** `shareIn(replay=1)` in the monitor.
- **PERF-17** — browse-cache eviction (H1 fix) bounds by age only, runs once per
  process, inserts never evict: within-session growth is unbounded and feeds
  PERF-3/PERF-4 costs. **Fix:** count cap + every-Nth-write sweep.
- **PERF-18** — `getFilterFacets` reads every `dto` blob for 3 columns
  (`ItemDao.kt:272-277`; `OfflineJellyfinRepository.kt:271-286`). **Fix:** 3-column
  projection (pattern ×3 in repo already).
- **PERF-19** — the tree's only production `runBlocking`
  (`StorageLocationManager.kt:100`) hides a DataStore read under the non-suspending
  `DownloadStorage.rootPath` surface; all current callers are on IO (verified) — latent,
  not live. **Fix:** seed cache from `appScope`; fall back to primary volume.
- **PERF-20** — four sites read the animating chrome padding in composition against
  `AppScaffold.kt:362-368`'s documented contract (`DownloadsScreen.kt:236,517`,
  `SearchScreen.kt:102,261`) — each nav transition frame becomes a full subcompose
  pass. **Fix:** pass `PaddingValues` through as Home/Libraries do.
